# Tiger backlog

Formal backlog is empty. Tiger init inventories the surface and records starting estimates; it
does not execute the lenses or turn static observations into certified findings. The first
tiger run will group findings by use case and rank them by frequency, reachability, trust erosion,
and cost. Every emitted item will name the governing registry standard.

## Strengths - protect, do NOT refactor away

- One provider dispatch and one Claude process-invocation seam centralize posture, timeouts,
  retry classification, schema state, usage, latency, and model identity.
- Judge prompts nonce-fence every untrusted input and carry an injection-suspected signal.
- Structured judge paths request schemas, validate typed values, repair once, and refuse phantom
  zeroes when every sample is unusable.
- Rubric scores clamp model values, compute weights/floors locally, support deterministic
  dimensions, and preserve sample coverage and agreement.
- Batch verdicts use stable case ids, rotate position, and retain batch-size/accounting provenance.
- Pairwise verdicts counterbalance order and collapse disagreement to a visible tie.
- HTTP target cost and token gaps remain null rather than invented.
- Gateway responses disclose route, served target, fallbacks, attempts, determinism, and schema state.
- Responder investigations are read-only; auto-fix is default-off, requires a clean tree, uses a
  dedicated branch, and keeps a failed commit visible rather than carrying edits onto the source branch.
- Device actions resolve paths locally, reject missing placeholders before spend, and keep prompt
  and result text private unless report_io is enabled.
