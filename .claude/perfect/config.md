## Gates

- `always:` `cargo fmt --all -- --check`, then `cargo clippy -p <changed crate> --all-targets -- -D warnings`,
  then `cargo test -p <changed crate>`. Whole-workspace builds are BANNED as a routine gate: a parallel
  session shares this checkout and `--workspace` pulls in their in-progress crates.
- `when a Store method changed:` `cargo test -p lighttrack-store --test sqlite_conformance`
  (`.ai/manifest.yaml` `capabilities.conformance`), plus the Postgres/Firestore parity read in
  `docs/PARITY.md` — a backend that silently defaults instead of implementing is a correctness bug,
  not a nicety (root CLAUDE.md).
- `when the judge prompt/scorer/fold changed:` `cargo test -p lighttrack-engine judge::tests::corpus`
  (`capabilities.judge-eval`) — the recorded-verdict replay. A moved number here is a change WE made.
- `when .ai/manifest.yaml or scripts/gates.sh changed:` `cargo test -p lighttrack-core --test manifest_guard`
  and `--test blocking_gate_guard`.
- `when a guidance/projection doc changed:` `cargo test -p lighttrack-core --test guidance_guard`.
- `slow:` live-provider runs (`lt-runner bench`, `lt-runner calibrate`) — they cost money and need
  `.env` keys; run in background from the repo root, read the output before the next state change.
- `builder:` fmt + clippy + test for the crates in the lot's write set ONLY. Never `--workspace`.

## Repo law

Digest pasted verbatim into every brief. The authoritative file is the **root `CLAUDE.md`**, declared
`guidance.canonical` in `.ai/manifest.yaml`. `.claude/CLAUDE.md` is a KNOWN-STALE projection
(`guidance.staleProjections`) — ignore it.

- **<= ~300 LOC per file.** Past it, split by responsibility. Many small single-purpose files.
- **`main.rs` is wiring only** — parse args / build router / dispatch. No business logic.
- **One module per domain**, not layer-mixing megafiles. Shared types in small dedicated modules;
  `lib.rs` = public types + `mod` + `pub use`, nothing heavy.
- **Store backends**: the trait stays in `crates/store/src/lib.rs`; a backend delegates each method to
  a per-domain submodule of free functions over a locked `&Connection` (`sqlite/events.rs`, ...);
  row mappers live beside their domain.
- **Backend parity is a correctness property.** A `Store` method one backend implements and another
  silently defaults is how caps and filters become advisory. Implement it, or return
  `StoreError::Unsupported` (-> 501). Never a quiet default.
- Cross-module helpers `pub(crate)`; only genuine API `pub`. **No `unwrap()` on fallible I/O in
  library code** — return `Result`. Tests live beside the code (`#[cfg(test)] mod tests`).
- Store timestamps are fixed-width `RFC3339(Nanos, Z)` so string range filters / `ORDER BY` are correct.
- **`lt-mcp`: all diagnostics to stderr** (stdout is JSON-RPC). Read tools are `readOnlyHint`; write
  tools stay behind `LIGHTTRACK_MCP_ALLOW_WRITES` (default off). Never expose secret-minting. The
  server is a thin HTTP client — never direct DB access.
- The judge/scoring engine is **unbudgeted**; limits apply only to monitored ingest traffic.
- Judge is **provider-configurable** (`judge_model = "[provider/]model"`), a structured generation
  parsed from the model's JSON text. Prefer a judge family different from the generator.
- Prices are **DB-backed** (`model_prices`, seeded from `config/pricing.json`).

**Out-of-scope walls:** `.env` and any secret file; `git push` (never automatic — the remote
`github.com/xkazm04/lighttrack` is PUBLIC); the store-selection block (Class C); `crates/store-pg/**`
is ordinary in-scope code again (the reservation was cleared 2026-08-03) but carries production
traffic on Neon, so it holds the same test/conformance bar as SQLite.

**Windows/build gotchas:** always `cargo build -p <crate>`, never `--workspace`. `cargo test` does NOT
refresh `target/debug/<bin>.exe` — rebuild before launching an exe. `lt-runner` loads `.env` from the
CURRENT directory: run it from the repo root.

**Parallel sessions share this checkout.** Stage explicit paths, never `-A`. Never `git stash`.

`/perfect smoke` therefore means:

  keys; treat it as a `slow` gate and ask before spending.

## User taste

- **Engine depth over chrome.** This repo has no UI; every direction is data model, algorithm,
  lifecycle, prompt/eval path or cost structure by construction.
- **Outcome-value over cosmetic churn.** A direction must name the operator moment it improves.

  contexts may be slated, not a hint.
